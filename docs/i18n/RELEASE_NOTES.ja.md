## 🎵 v5.5.0 — LLM別オーディオルーティング & Windows インストーラーの堅牢化

**リリース日:** 2026-04-27

### 🆕 LLM別オーディオルーティング
各 LLM（Claude Code、Copilot、Codex）が独自のボイス、プリテキスト、リバーブ、BGM設定を持てるようになりました。
MCP サーバーは `--llm <key>` を `play-tts.sh`（Linux/macOS）と `play-tts.ps1`（Windows）の両方に渡し、
スクリプトは `audio-effects.cfg` の `llm:<key>` 行を参照します。`claude-code`、`copilot`、`codex` 用の
デフォルト行が同梱されており、TUI の **Setup → Default → Configure** で設定できます。

### 🐛 Windows インストーラークラッシュの修正
古いグローバルインストールを持つユーザーが Windows で AgentVibes を**再インストール**した際に発生していた
`spinner.info is not a function` エラーを修正しました。インストーラー内の 10 個のファイルコピー関数がすべて
`createRobustSpinner()` でスピナーをラップするようになり、どのメソッドを公開しているかに関わらず
古いコードがクラッシュを引き起こすことはなくなりました。

### 🎶 Windows バックグラウンド音楽のパリティ
Windows TTS 再生は、低品質の WinMM `SoundPlayer` リサンプラーより `ffplay`（Sinc リサンプリング、アーティファクトなし）を
優先するようになりました。新しい `Invoke-AudioPlay` ヘルパーがフォールバックを透過的に処理します —
`ffplay` が利用できない場合は従来通り `SoundPlayer` が使用されます。

### 🎉 パーティモードのクロスプラットフォームエントリポイント
BMAD パーティモードのステップファイルと Copilot スキルが、一貫して `node bin/bmad-speak.js` を参照するようになりました —
Windows では `bmad-speak.ps1` に、それ以外では `bmad-speak.sh` に委譲する単一のクロスプラットフォームエントリポイントです。

### 🔧 その他の修正
- `play-tts.sh` が環境変数 `LLM_PROVIDER` に加えて、名前付きフラグ `--llm <key>` を受け付けるようになりました
- `mcp-server/server.py` が優先チェーン `AGENTVIBES_LLM` → `CLAUDECODE=1` → `AGENTVIBES_MCP_FALLBACK` でルーティングし、
  解決されたキーを `-llm`/`--llm` として TTS スクリプトに渡します
- `audio-effects.cfg` に `llm:claude-code`、`llm:copilot`、`llm:codex` の行を追加
- `command-routing.test.js` と `ConfigService` のユニットテストを追加
- npm pack コンテンツガードが追跡されていない公開対象ファイルを検出するようになりました

### 📊 技術
- 231 テスト通過（失敗 0）

## 🎯 v5.3.0 — リモートボイスを思いのままに

**リリース日:** 2026年4月

サーバーから携帯電話、ノートパソコン、あるいは別のマシンへ音声アナウンスを送るために AgentVibes を使っているなら、このリリースで主導権はあなたの手に戻ります。すべての呼び出しで、ボイス、BGM、イントロフレーズ、リバーブ、ボリューム、速度をそれぞれ個別に選べるようになりました — コマンドラインから、そのメッセージ 1 件のためだけに。

### ✨ 新機能

#### すべてのアナウンスを個別にカスタマイズできるように

これまでは、1 件のメッセージだけ別のボイスや音楽にしたい場合、設定ファイルを書き換える必要がありました(そして元に戻すのを覚えておかなければなりませんでした)。今はコマンドにフラグを追加するだけです。

このデプロイ通知だけは Winston のイギリス訛りでジャズと共に届けたい? 簡単です:

```bash
bash .claude/hooks/play-tts-ssh-remote.sh \
  --text "Deploy complete" \
  --voice "en_US-ryan-high" \
  --pretext "Winston here" \
  --music "Late Night Hip Hop Groove.mp3" \
  --volume 0.25
```

指定しなかった項目は、通常の設定にフォールバックします。今回だけイントロフレーズを飛ばしたい? `--pretext ""` を渡せば、メッセージの前は無音になります。

**利用可能なフラグ:**
- `--voice` — 使用する Piper ボイス
- `--pretext` — メッセージの前に流すイントロフレーズ (`""` を渡すとスキップ)
- `--music` — BGM のトラック (スペース入りのファイル名も動作するようになりました!)
- `--volume` — BGM の音量 (0.0 〜 1.0)
- `--effects` — リバーブなどのサウンドエフェクトチェイン
- `--speed` — ボイスの発話速度
- `--provider` — 使用する TTS エンジン
- `--agent` — 使用するエージェントパーソナリティ

従来の呼び出し方も引き続き動作するので、既存のセットアップが壊れることはありません。

### 🛠 信頼性の修正

- **長文メッセージと特殊文字が途中で切れなくなりました。** Windows では、長いアナウンスや引用符・アポストロフィ・絵文字を含むテキストが、ボイスエンジンに届く前に文字化けしていました。修正済み — メッセージがどれだけ長くても奇妙でも、送った通りに届きます。

- **モニターのない Windows サーバーでもボイスアナウンスが機能するように。** Windows は SSH が通常使用する「サービス」セッションではオーディオ再生を拒否します。小さなバックグラウンドヘルパーが通常のユーザーセッションで動作し、キューからアナウンスを取り出すので、ヘッドレスサーバーでもオーディオが正しく再生されます。

- **TUI のボイスプレビューがリモートサーバーで動作するように。** これまでは、スピーカーのないサーバーからボイスをプレビューすると、ローカルで再生しようとして失敗していました。現在は、設定済みのリモートデバイスへ正しくストリーミングされます。

- **イントロフレーズの二重発話を解消。** 送信サーバーと受信マシンの両方にプリテキストを設定していると、これまでは 2 回聞こえていました。今は送信側が優先され、受信側は自前のものを上乗せしません。

- **リモートストリーミング設定が実際に反映されるように。** 最近の変更で、リモートストリーミング構成 (`ssh-remote`、`agentvibes-receiver`) が誤って上書きされ、ローカル再生にフォールバックする問題が発生していました。修正済み。

- **長文アナウンスが途中で強制終了されなくなりました。** 詰まったオーディオを停止するための安全タイムアウトが、長いメッセージに対して厳しすぎました。段落単位のアナウンスも扱えるよう十分に余裕を持たせました。

- **よりクリーンなインストーラーの状態** — Claude Code 向けに AgentVibes をインストールする際、暗黙の状態に依存せず、TTS プロバイダーファイルを明示的に書き込むようになりました。

### 🧪 テスト

BMAD パーティモードが動き続けることを保証する 55 件の新規テスト: 各エージェントが固有のボイスと音楽を持つこと、エージェント同士が同じ Piper スピーカー ID を誤って共有しないこと、インストーラーが常にクロスプラットフォームのエントリポイントをパーティモードに向けること。

## 🎯 v5.2.1 — マルチLLMアイデンティティ & インストール磨き上げ

**リリース日:** 2026年4月

Copilot/Codex 向けの LLM ルーティングを洗練し、セットアップ体験をリファインしました。

### ✨ 新機能

#### マルチLLMアイデンティティ・ルーティング

- **GitHub Copilot に独自のボイス、プリテキスト、BGM が追加** — Claude Code や Codex とは完全に区別されます。ボサノバに乗せて "Copilot here" とご挨拶。

- **明示的なアイデンティティを持つツールごとの MCP 設定** — 各 AI ツール (`.vscode/mcp.json`、`.codex/config.toml`、`~/.copilot/mcp-config.json`) が独自の `AGENTVIBES_LLM` を設定するので、ルーティングが決定論的に。

- **MCP ツール `get_config` が検出された LLM を返すように** — 呼び出し側のアシスタントがルーティングを確認し、最初から正しいボイスで応答できます。

- **Linux 互換性のリファイン** — CRLF 行末、パーミッション、トランスポートプロバイダーのオーバーライド処理。

#### セットアップフロー改善

- **キーボードナビゲーションフロー** — インストールボタン (Claude → Copilot → Codex) で Enter を押すと、次は **Claude 設定** にジャンプし、3 つの設定ボタンを順に通ってからデフォルトに到達します。

- **インストール/削除列からデフォルト行をスキップ** — 下矢印キーがデフォルト行を飛ばします。

- **部分的成功のインストールメッセージ** — ファイルコピーは成功したが MCP 設定が少し調整を要する場合、汎用的な失敗ではなく明確な警告が表示されます。

#### デフォルト値

- **Claude Code のデフォルト BGM** を Chillwave (`agent_vibes_chillwave_v2_loop.mp3`) に設定。

#### 内部的な改善

- LLM キーバリデーションを強化し、環境変数の扱いをより安全に。
- Copilot CLI 設定書き込みのエッジケースに対するエラーロギングを改善。
- 既知の制限を文書化: Claude Code 起動のターミナルから VS Code を起動すると `CLAUDECODE=1` が漏れる可能性があります — 回避策は先に `unset CLAUDECODE` すること。

## 🎯 v5.2.0 — リモートボイスプレビュー + ケーブマンモード + ボイスレーティング

**リリース日:** 2026年4月

このリリースでは、リモートTTSプレビューのサポート、新しい超簡潔な詳細度モード、TUI全体へのサムズアップ/ダウンによる音声評価機能を追加しました。

### 新機能

- **ケーブマン詳細度モード** — 超簡潔なTTS出力のための新しい `caveman` 詳細度レベル。文章ではなく断片で出力されます。`/agent-vibes:verbosity caveman` またはMCPの `set_verbosity` ツールで設定できます。インストール直後に音声が一つもない場合、自動的にダウンロードします。

- **サムズアップ/ダウン音声評価** — 旧来のスターお気に入りを 👍/👎 評価に置き換えました。Voicesタブおよびボイスピッカー（Setupタブ）の両方で、`+` でサムズアップ、`-` でサムズダウンを押せます。評価はセッションをまたいで保持され、すべての音声選択UIで共有されます。

- **リモートボイスプレビュー** — TUI Voicesタブ、ボイスピッカー、ボイスブラウザーでのボイスプレビューが、ヘッドレスサーバーでも動作するようになりました。アクティブなプロバイダーが `ssh-remote` または `agentvibes-receiver` の場合、プレビューは `play-tts.sh` を経由してリモートレシーバーでオーディオを再生します（ローカルのPiperとオーディオプレーヤーは不要）。プラットフォーム対応: WindowsではPowerShell、LinuxではBashを使用します。

- **SSHレシーバープロバイダーのルーティング** — `ssh-remote` と `agentvibes-receiver` が `play-tts.sh` のファーストクラスプロバイダーになりました。`speak_text()` 関数とメインルーティングのcaseステートメントの両方でサポートされ、「Unknown provider」エラーが解消されました。

### 修正

- **LibriTTSスピーカー名の自動パッチ** — 音声ダウンロード時にLibriTTSスピーカー名を自動的にパッチするようになり、マルチスピーカー音声が最初から正しく動作します。
- **音声バリデーション正規表現の強化** — `play-tts-ssh-remote.sh` および `play-tts-agentvibes-receiver.sh` のVOICEパラメーター正規表現が、バックスラッシュ（インジェクションリスク）を除きながら `::`（マルチスピーカー）、`.`（ロケール）、スペース（スピーカー名）を許可するようになりました。LinuxおよびWindowsレシーバーテンプレートも合わせて更新されました。
- **`base64` クロスプラットフォーム対応** — `play-tts-agentvibes-receiver.sh` がGNUの `base64 -w 0` を試み、BSDの `-b 0` にフォールバックし、さらに `tr -d '\n'` にフォールバックするようになりました。macOS/BSDシステムでのスクリプト中断を修正します。
- **オーディオエフェクト二重処理の修正** — `AGENTVIBES_NO_PLAY` が設定されている場合、`play-tts-piper.ps1` が自身のオーディオプロセッサー呼び出しをスキップし、リバーブ/ミュージックが二重に適用されるのを防ぎます。
- **終了コードリークの修正** — `play-tts.ps1` が明示的にコード0で終了するようになり、ネイティブコマンドの終了コード（piper、ffmpeg、sox）がリークして誤ったTTS失敗レポートを引き起こすのを防ぎます。
- **Windowsレシーバータブのプラットフォームサポート** — TailscaleのIP検出、PowerShell経由のローカルIP、sshd_configの読み取り、クリップボードへのコピーがWindowsでネイティブに動作するようになりました。
- **`llm:default` オーディオエフェクト行** — `audio-effects.cfg` に新しいデフォルト行が追加され、LLM別設定エントリがない場合でもリモートレシーバーがリバーブ、ミュージック、プリテキストを受け取れるようになりました。
- **プレビューサンプルテキスト** — Piperの「preview」という単語の発音不具合を回避するため変更されました。
