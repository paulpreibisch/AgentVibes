## 🔧 v5.13.1 — 本当に更新される Windows の更新

**リリース日:** 2026-07-16 · `latest` で公開中 — `npm install agentvibes@latest`

### 🪟 あなたの Windows 用スクリプトが、今度こそ本当に更新されます

Windows では、エージェントに話をさせる小さなスクリプトが `.claude/hooks` フォルダの中にあります。更新のたびに「更新しました」と表示されていましたが、実は Windows ではこっそり更新されておらず、最初にインストールしたときのバージョンのまま何か月も放置されることがありました。

これからは本当に更新されます。`npx agentvibes update` を実行すれば、見逃していた修正をすべて受け取れます。あなた自身が変更したファイルは、これまでと同じように `.user.bak` というファイルとして隣に安全に保存されます。

macOS や Linux を使っている場合は何も変わりません — そちらではもともと更新はきちんと動いていました。

### 🔒 内部のセキュリティもひとつ底上げしました

AgentVibes が設定ファイルを読み込むときに使っている部品のひとつを更新しました。特殊な細工がされた設定ファイルを読み込むと、動きが止まってしまうことがありました。何かが盗み見られたり持ち出されたりすることは一度もありませんでしたが、これからは止まってしまうこともなくなります。あなたが何かをする必要はありません — すでに反映されています。

## 🎉 v5.13.0 — あなたの音声をどこでも、お知らせ付きで

**リリース日:** 2026-07-16 · `latest` で公開中 — `npm install agentvibes`

新機能:

Piper、Kokoro、ElevenLabs、Windows、Mac、Soprano — すべての音声が単一のリストから提供されるようになったので、目に見えるものが常に使えるものです。

### 🔔 音が鳴る前の「お知らせ」チャイム
音声のセリフや音楽プレビューが始まる直前に、短いチャイムが鳴ります — たとえ少し時間がかかっても、音声がやってくることが常にわかります。

### 🎵 音楽プレビューが音の行き先に従う
トラックをプレビューすると、あなたの音声設定で指定された場所で再生されます — 別のコンピューターでも同様です。

自己紹介をオンにすると、各エージェントは開始時に自分が誰であるかを話します — チーム全体が話しているときに便利です。

`.claude/hooks` フォルダ内の AgentVibes のファイルをいじったことはありますか? このバージョンからは、更新であなたの作業が消えることはありません。あなたが変更したファイルを更新する必要があるとき、その隣にあなたのコピーを `.user.bak` を付けて残します — `play-tts.sh.user.bak` のように。

**そのファイルは AgentVibes が作ったものです — 何も壊れていませんし、他の誰かが置いたものでもありません。** それは単にあなたの古いバージョンで、見比べたり、変更内容を新しいファイルにコピーし戻したりできるように保存されているだけです。用が済んだらいつでも削除してかまいません。

古いバージョンでファイルをカスタマイズしていた場合は、`.claude/hooks` の中を一度覗いて、戻したいものがないか確認する価値があります。

### ✨ より多くの音声、よりスムーズな体験
- **ElevenLabs** の音声を完全サポート
- より多くの **Kokoro** 音声、Windows でも快適に動作
- Windows でより速く、より信頼性の高いセットアップ
- **3,263 件の自動テストに合格** — 安定して頼れる品質

## 🎉 v5.12.0 — Fable Week 大改修（安定版）

**リリース日:** 2026-07-05 · `latest` で公開中 — `npm install agentvibes`

これは「Fable Week」アルファ版を安定版リリースへと仕上げたものです。Anthropic の新しい **Fable** モデルへの1週間の早期アクセス期間中、私たちはそれを AgentVibes のコードベース全体に向け、コアを正しく作り直しました。

### より強固な、共有されたコア

AgentVibes が話すたびに、多くの判断が行われます — どの音声を使うか、どのエンジンを使うか、この場で再生するか別のマシンに音声を送るか、バックグラウンドミュージック、音量、ミュート。そのロジックはいくつかの別々のスクリプト（Mac/Linux、Windows、リモート、そして音声サーバー）にコピーされており、コピーは少しずつ**互いに食い違って**いきました — 一方で修正した内容が他方では反映されず、それが特定の不具合が再発し続ける原因でした。

私たちはそのすべてを、AgentVibes のあらゆる部分が従う**単一の共有コア**に置き換えました — 修正する場所は一箇所、信頼できる場所も一箇所です。あなたが実感できること:

- **Linux で無音だった Kokoro 音声が、どこでも動作するようになりました。**
- **音声の選択が保持されます** — 設定がひそかに上書きされることはなくなりました。
- **音量、ミュート、リモート再生が同じように動作します** — Mac、Linux、Windows のいずれでも。
- **デフォルトで安全** — お使いのマシンで新しいコアが利用できない場合、AgentVibes は従来の動作にフォールバックするため、話すのを突然やめることはありません。

### プレビューが正しい場所で再生されるように

以前は、音声やトラックのプレビューは、あなたが操作しているマシンで再生されていました — 音声を別の場所へ送るように AgentVibes を設定していた場合、それは無音でした。今後は:

- **SSH リモートを設定している場合、プレビューはレシーバーで再生されます。設定していない場合は、これまで通りローカルで再生されます。**
- これは Setup、Agent、Settings の各画面からの**音声プレビュー**（Piper と Kokoro）、そして**音楽/トラックのプレビュー**をカバーします — Space キーで再生、もう一度 Space キーで停止します。

### よりシンプルな音声メニュー

- **冗長だった Voices タブを削除しました。** それは Piper 音声しか一覧表示せず、混乱を招いていました。どのプロバイダーの音声を選ぶ場合でも、すでに **Setup** で行えるからです。

### 次に向けた地ならし

- レシーバーは、メッセージの送信元となった**プロジェクトフォルダの完全パス**も受け取るようになりました（すでに受け取っていたプロジェクト名に加えて、新しい `projectPath` フィールド）— 今後の機能強化に向けた地ならしです。

### 出荷前のレビュー

私たちは変更に対して3つの独立したレビュー — セキュリティ、正確性、リグレッション — を実施し、リリース前に実際の問題をすべて修正しました。

## 🎸 v5.8.0 — Sopranoが動作するように + 全エンジン対応の音声ピッカーを修正

**リリース日:** 2026-05-18

### 🐛 Soprano TTSが動作していなかった — 修正済み

Soprano（v5.6で導入した80Mパラメータのニューラル音声合成エンジン）はWindowsで静かに失敗していました。複数の問題が組み合わさって、全体が動作しない状態になっていました：

- Windowsの音声ピッカーはSopranoをオプションとして表示しましたが、誤ったバイナリ名（`soprano`の代わりに`soprano-tts`）で起動しようとしていました
- `play-tts-soprano.ps1`はNode.jsから不完全なPATHで呼び出されていたため、インストールされていても`soprano`と`soprano-webui`の実行ファイルが見つかりませんでした
- wavファイルのパスはstdoutではなくPowerShellのInformationストリーム（`Write-Host`）に書き込まれていたため、リバーブ/バックグラウンドミュージックプロセッサがパスを見つけられませんでした
- Gradio WebUIは自動起動していなかったため、毎回セッション前に手動で`soprano-webui`を実行する必要がありました

これらすべての問題が修正されました。AgentVibesはポート7860でSopranoのWebUIサーバーが実行中かどうかを自動検出し、起動していない場合は起動して準備が整うまでポーリングします（最大90秒）。3つのモードが優先順位順で動作します：WebUI（最速 — モデルがロード済みのまま）→ OpenAI互換API → `soprano` CLI直接実行。

### 🐛 音声ピッカーがWindows SAPIとmacOS Sayを無視していた

**Windows SAPI**または**macOS Say**を使用するように設定されたLLMの音声ピッカーを開くと、エンジン内蔵の音声ではなくPiperの全ボイスリストが表示されていました。これは混乱を招くものでした — SAPIやmacOS Sayを使用中にPiperの音声を選択しても効果がなく、スペースバーのプレビューも誤ったエンジンを通じて再生されていました。

ピッカーは選択されたエンジンに合わせて適応するようになりました：

- **Windows SAPI / macOS Say / Soprano:** エンジン内蔵の音声の1項目のみ表示し、自動選択し、スペースバープレビューは正しいエンジンバイナリを通じて発音されます
- **Piper:** 従来通り、インストールされている全ボイスカタログを表示

また、設定を保存しても、ネイティブエンジンが使用中の場合、`ttsEngine`フィールドが`piper`に静かに上書きされることはなくなりました。

### 🔒 Sopranoの信頼性（アドバーサリアルレビューによる9つの修正）

- **クラッシュ修正:** ソケットの`destroy()`がリスナーのない遅延`error`イベントを発行し、Node.jsプロセスをクラッシュさせる可能性がありました — アブゾーバーハンドラが追加されました
- **ループキャンセル:** モーダルや音声ピッカーが閉じられると、90秒のWebUIポーリングループが即座に停止します（AbortController経由）
- **未処理のリジェクションなし:** 全ての非同期WebUIチェック呼び出しに`.catch()`ハンドラを追加
- **重複プロセスなし:** プレビューを素早くクリックした際に2つの`soprano-webui`インスタンスが起動するのを防ぐ10秒のクールダウン
- **より良いエラーフィードバック:** spawnの失敗や非ゼロの終了コードが音声ピッカーに表示エラーラベルとして表示されるようになりました
- **PATHを保持:** PowerShellのPATHリフレッシュはPATH全体を置き換える代わりにレジストリエントリを追加するようになり、nvm、conda、pyenvのシムが引き続き機能します

VoicesタブとAgentsタブの選択された行に白いテキストが正しく表示されるようになった。以前は`bright-black`フォアグラウンドと緑の背景の組み合わせが多くのターミナルで読みにくいグレーテキストを生成していた。

## 🔧 v5.7.6 — SSHリモートペイロードの整合性とレシーバーの全面書き直し

**リリース日:** 2026-05-16

### 🐛 SSHリモートが間違った音楽と音声を再生

SSHリモートTTS機能を使用すると、間違ったプロジェクトの音楽トラックと音声が適用されていました。根本原因: `CLAUDE_PROJECT_DIR` が送信者に転送されず、アクティブなプロジェクトの `audio-effects.cfg` の代わりにグローバル設定が使用されていました。

### 🐛 BashレシーバーがJSONペイロード形式と非互換

Linux/Termux bashレシーバー (`agentvibes-receiver.sh`) はv5.5以前の位置引数形式を使用しており、現在のbase64 JSONペイロードをまったくデコードできませんでした。レシーバーはPowerShellレシーバーのロジックに合わせて完全に書き直されました: base64をデコードし、JSONを解析し、音声/音楽/エフェクト/音量を適用し、すべてのフィールドを検証します。

### 🐛 パーソナリティイントロがリモートで二回再生される

パーソナリティpretext（例: "Bcs latin dance here"）がSSHリモートTTS使用時に二回話されていました。根本原因: `play-tts.sh` は送信者を呼び出す前にpretextをスピーチテキストに先頭追加しており、送信者もそれをJSONの `pretext` フィールドにパックしていたため、レシーバーが再度先頭追加していました。JSONの `pretext` フィールドは意図的に空のままにされています — パーソナリティは `text` フィールドのみで配信されます。

### 🆕 設定タブにSSHホストエイリアスが表示される

設定済みのSSHリモートホストエイリアスが設定タブとボイスタブに表示されるようになり、設定ファイルを開かずにTTSが対象とするリモートマシンを確認できます。

### 🔒 セキュリティ修正

SSHリモート送信者とレシーバーの入力検証の改善。

### 🧪 24個の新しいBATSテスト

- 15個のSSHリモートペイロードテスト: 音声、音楽トラック、音量、リバーブ/エフェクト、pretext処理、LLM識別子、プロジェクト設定の優先順位、JSON有効性を検証
- 9個のエンドツーエンドの往復テスト: 送信者がペイロードを構築 → レシーバーがすべてのフィールドを同時にデコードして適用し、どちらの端の回帰も検出

## 🖥️ v5.7.5 — TUI ボタンコントラスト + BMAD ルーティング修正

**リリース日:** 2026-05-13

### 🐛 TUI ボタンフォーカス: 全ターミナルでグレーテキストを排除

TUI（ボイス、ミュージック、設定、セットアップタブ）のフォーカス・選択ボタンが、多くのターミナルで薄いグレーのテキストを水色背景に表示していました。根本原因: `bold: true` と暗い前景色の組み合わせがターミナルの「ブライトモード」を起動し、正確な色合いに関係なくグレーとしてレンダリングします。

**修正:** すべてのボタンフォーカス状態が**ダークグリーン背景（`#2e7d32`）に白いテキスト**を使用するようになりました — エージェントタブで既に使用されているのと同じ高コントラストパターンです。`attachBtnBlink` が blessed のパッシブ `style.focus` カラー適用に干渉しないよう、setup-tab モーダルボタンに明示的な `focus`/`blur` ハンドラーが追加されました。

### 🐛 BMAD タブのボイスピッカー ♪ インジケーターが表示されない

BMAD タブのボイスリストの ♪ プレビューインジケーターがプレビュー中に表示されませんでした。エージェントタブには設定タブが既に持っていた `_refreshVP()` 呼び出しが欠けていました。SSH-remote が即座に終了する場合（fire-and-forget モード）でも、2秒の最小表示タイマーでインジケーターを表示し続けます。

### 🐛 非インタラクティブインストール: プロジェクト名ではなく汎用プレテキスト

`agentvibes install` を非インタラクティブで実行すると、プロジェクトに関係なく常にプレテキストが `"Claude Code here"` に設定されていました。インストーラーは `path.basename(process.cwd())` から大文字化したプロジェクト対応プレテキストを導出するようになりました（例: `"MyProject here"`）。Docker ルートパスには安全なフォールバックがあります。

### 🐛 グローバルプレテキストがプロジェクトごとの設定を上書き

`seedAllLlmDefaultsSync` がプロジェクトレベルの LLM 行にグローバルプレテキスト文字列をシードしており、グローバルの `"Claude Code here"` がプロジェクトごとの `tts-pretext.txt` の値を上書きしていました。プロジェクトレベルの行は空のプレテキストでシードされるようになり、プロジェクトごとのファイルが優先されます。

### 🐛 `screen`/`tmux` TERM バリアントが `plab_norm` 機能エラーを引き起こす

`TERM` が `screen-*` または `tmux-*` バリアントに設定されている場合、blessed が起動時に `plab_norm` ターミナル機能エラーをスローしていました。そのようなバリアントが検出された場合、アプリは blessed 画面を作成する前に `TERM` を `xterm-256color` にオーバーライドするようになりました。

### 🐛 BMAD エージェントごとのミュージック/リバーブが SSH レシーバーに届かない

`play-tts.sh` が `AGENT_PROFILE_FILE` を SSH リモートトランスポートに転送していなかったため、BMAD タブで設定されたエージェントごとの BGM とリバーブのオーバーライドがリモートオーディオに対してサイレントに無視されていました。プロファイルファイルパスが `play-tts-ssh-remote.sh` への引数 4 として渡されるようになりました。

### 🐛 Node 18 互換性: `import.meta.dirname` を置換

テストファイルが Node 21+ でのみ利用可能な `import.meta.dirname` を使用していました。Node 18 と 20 でテストが正常に実行されるよう、`fileURLToPath(import.meta.url)` パターンに置換されました。

## 🎯 v5.3.0 — リモートボイスを思いのままに

**リリース日:** 2026年4月

サーバーから携帯電話、ノートパソコン、あるいは別のマシンへ音声アナウンスを送るために AgentVibes を使っているなら、このリリースで主導権はあなたの手に戻ります。すべての呼び出しで、ボイス、BGM、イントロフレーズ、リバーブ、ボリューム、速度をそれぞれ個別に選べるようになりました — コマンドラインから、そのメッセージ 1 件のためだけに。

### ✨ 新機能

#### すべてのアナウンスを個別にカスタマイズできるように

これまでは、1 件のメッセージだけ別のボイスや音楽にしたい場合、設定ファイルを書き換える必要がありました(そして元に戻すのを覚えておかなければなりませんでした)。今はコマンドにフラグを追加するだけです。

このデプロイ通知だけは Winston のイギリス訛りでジャズと共に届けたい? 簡単です:

```bash
bash .claude/hooks/play-tts-ssh-remote.sh \
  --text "Deploy complete" \
  --voice "en_US-ryan-high" \
  --pretext "Winston here" \
  --music "Late Night Hip Hop Groove.mp3" \
  --volume 0.25
```

指定しなかった項目は、通常の設定にフォールバックします。今回だけイントロフレーズを飛ばしたい? `--pretext ""` を渡せば、メッセージの前は無音になります。

**利用可能なフラグ:**
- `--voice` — 使用する Piper ボイス
- `--pretext` — メッセージの前に流すイントロフレーズ (`""` を渡すとスキップ)
- `--music` — BGM のトラック (スペース入りのファイル名も動作するようになりました!)
- `--volume` — BGM の音量 (0.0 〜 1.0)
- `--effects` — リバーブなどのサウンドエフェクトチェイン
- `--speed` — ボイスの発話速度
- `--provider` — 使用する TTS エンジン
- `--agent` — 使用するエージェントパーソナリティ

従来の呼び出し方も引き続き動作するので、既存のセットアップが壊れることはありません。

### 🛠 信頼性の修正

- **長文メッセージと特殊文字が途中で切れなくなりました。** Windows では、長いアナウンスや引用符・アポストロフィ・絵文字を含むテキストが、ボイスエンジンに届く前に文字化けしていました。修正済み — メッセージがどれだけ長くても奇妙でも、送った通りに届きます。

- **モニターのない Windows サーバーでもボイスアナウンスが機能するように。** Windows は SSH が通常使用する「サービス」セッションではオーディオ再生を拒否します。小さなバックグラウンドヘルパーが通常のユーザーセッションで動作し、キューからアナウンスを取り出すので、ヘッドレスサーバーでもオーディオが正しく再生されます。

- **TUI のボイスプレビューがリモートサーバーで動作するように。** これまでは、スピーカーのないサーバーからボイスをプレビューすると、ローカルで再生しようとして失敗していました。現在は、設定済みのリモートデバイスへ正しくストリーミングされます。

- **イントロフレーズの二重発話を解消。** 送信サーバーと受信マシンの両方にプリテキストを設定していると、これまでは 2 回聞こえていました。今は送信側が優先され、受信側は自前のものを上乗せしません。

- **リモートストリーミング設定が実際に反映されるように。** 最近の変更で、リモートストリーミング構成 (`ssh-remote`、`agentvibes-receiver`) が誤って上書きされ、ローカル再生にフォールバックする問題が発生していました。修正済み。

- **長文アナウンスが途中で強制終了されなくなりました。** 詰まったオーディオを停止するための安全タイムアウトが、長いメッセージに対して厳しすぎました。段落単位のアナウンスも扱えるよう十分に余裕を持たせました。

- **よりクリーンなインストーラーの状態** — Claude Code 向けに AgentVibes をインストールする際、暗黙の状態に依存せず、TTS プロバイダーファイルを明示的に書き込むようになりました。

### 🧪 テスト

BMAD パーティモードが動き続けることを保証する 55 件の新規テスト: 各エージェントが固有のボイスと音楽を持つこと、エージェント同士が同じ Piper スピーカー ID を誤って共有しないこと、インストーラーが常にクロスプラットフォームのエントリポイントをパーティモードに向けること。

## 🎯 v5.2.1 — マルチLLMアイデンティティ & インストール磨き上げ

**リリース日:** 2026年4月

Copilot/Codex 向けの LLM ルーティングを洗練し、セットアップ体験をリファインしました。

### ✨ 新機能

#### マルチLLMアイデンティティ・ルーティング

- **GitHub Copilot に独自のボイス、プリテキスト、BGM が追加** — Claude Code や Codex とは完全に区別されます。ボサノバに乗せて "Copilot here" とご挨拶。

- **明示的なアイデンティティを持つツールごとの MCP 設定** — 各 AI ツール (`.vscode/mcp.json`、`.codex/config.toml`、`~/.copilot/mcp-config.json`) が独自の `AGENTVIBES_LLM` を設定するので、ルーティングが決定論的に。

- **MCP ツール `get_config` が検出された LLM を返すように** — 呼び出し側のアシスタントがルーティングを確認し、最初から正しいボイスで応答できます。

- **Linux 互換性のリファイン** — CRLF 行末、パーミッション、トランスポートプロバイダーのオーバーライド処理。

#### セットアップフロー改善

- **キーボードナビゲーションフロー** — インストールボタン (Claude → Copilot → Codex) で Enter を押すと、次は **Claude 設定** にジャンプし、3 つの設定ボタンを順に通ってからデフォルトに到達します。

- **インストール/削除列からデフォルト行をスキップ** — 下矢印キーがデフォルト行を飛ばします。

- **部分的成功のインストールメッセージ** — ファイルコピーは成功したが MCP 設定が少し調整を要する場合、汎用的な失敗ではなく明確な警告が表示されます。

#### デフォルト値

- **Claude Code のデフォルト BGM** を Chillwave (`agent_vibes_chillwave_v2_loop.mp3`) に設定。

#### 内部的な改善

- LLM キーバリデーションを強化し、環境変数の扱いをより安全に。
- Copilot CLI 設定書き込みのエッジケースに対するエラーロギングを改善。
- 既知の制限を文書化: Claude Code 起動のターミナルから VS Code を起動すると `CLAUDECODE=1` が漏れる可能性があります — 回避策は先に `unset CLAUDECODE` すること。

## 🎯 v5.2.0 — リモートボイスプレビュー + ケーブマンモード + ボイスレーティング

**リリース日:** 2026年4月

このリリースでは、リモートTTSプレビューのサポート、新しい超簡潔な詳細度モード、TUI全体へのサムズアップ/ダウンによる音声評価機能を追加しました。

### 新機能

- **ケーブマン詳細度モード** — 超簡潔なTTS出力のための新しい `caveman` 詳細度レベル。文章ではなく断片で出力されます。`/agent-vibes:verbosity caveman` またはMCPの `set_verbosity` ツールで設定できます。インストール直後に音声が一つもない場合、自動的にダウンロードします。

- **サムズアップ/ダウン音声評価** — 旧来のスターお気に入りを 👍/👎 評価に置き換えました。Voicesタブおよびボイスピッカー（Setupタブ）の両方で、`+` でサムズアップ、`-` でサムズダウンを押せます。評価はセッションをまたいで保持され、すべての音声選択UIで共有されます。

- **リモートボイスプレビュー** — TUI Voicesタブ、ボイスピッカー、ボイスブラウザーでのボイスプレビューが、ヘッドレスサーバーでも動作するようになりました。アクティブなプロバイダーが `ssh-remote` または `agentvibes-receiver` の場合、プレビューは `play-tts.sh` を経由してリモートレシーバーでオーディオを再生します（ローカルのPiperとオーディオプレーヤーは不要）。プラットフォーム対応: WindowsではPowerShell、LinuxではBashを使用します。

- **SSHレシーバープロバイダーのルーティング** — `ssh-remote` と `agentvibes-receiver` が `play-tts.sh` のファーストクラスプロバイダーになりました。`speak_text()` 関数とメインルーティングのcaseステートメントの両方でサポートされ、「Unknown provider」エラーが解消されました。

### 修正

- **LibriTTSスピーカー名の自動パッチ** — 音声ダウンロード時にLibriTTSスピーカー名を自動的にパッチするようになり、マルチスピーカー音声が最初から正しく動作します。
- **音声バリデーション正規表現の強化** — `play-tts-ssh-remote.sh` および `play-tts-agentvibes-receiver.sh` のVOICEパラメーター正規表現が、バックスラッシュ（インジェクションリスク）を除きながら `::`（マルチスピーカー）、`.`（ロケール）、スペース（スピーカー名）を許可するようになりました。LinuxおよびWindowsレシーバーテンプレートも合わせて更新されました。
- **`base64` クロスプラットフォーム対応** — `play-tts-agentvibes-receiver.sh` がGNUの `base64 -w 0` を試み、BSDの `-b 0` にフォールバックし、さらに `tr -d '\n'` にフォールバックするようになりました。macOS/BSDシステムでのスクリプト中断を修正します。
- **オーディオエフェクト二重処理の修正** — `AGENTVIBES_NO_PLAY` が設定されている場合、`play-tts-piper.ps1` が自身のオーディオプロセッサー呼び出しをスキップし、リバーブ/ミュージックが二重に適用されるのを防ぎます。
- **終了コードリークの修正** — `play-tts.ps1` が明示的にコード0で終了するようになり、ネイティブコマンドの終了コード（piper、ffmpeg、sox）がリークして誤ったTTS失敗レポートを引き起こすのを防ぎます。
- **Windowsレシーバータブのプラットフォームサポート** — TailscaleのIP検出、PowerShell経由のローカルIP、sshd_configの読み取り、クリップボードへのコピーがWindowsでネイティブに動作するようになりました。
- **`llm:default` オーディオエフェクト行** — `audio-effects.cfg` に新しいデフォルト行が追加され、LLM別設定エントリがない場合でもリモートレシーバーがリバーブ、ミュージック、プリテキストを受け取れるようになりました。
- **プレビューサンプルテキスト** — Piperの「preview」という単語の発音不具合を回避するため変更されました。
